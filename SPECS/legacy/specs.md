# Спецификация извлечения UI Kit → машиночитаемые артефакты

Версия: 1
Дата: 2026-07-28
Источник: `ui-kit-eds-ce` (`sds-eng`, `@sds-eng/base@1.3.1`, `@sds-eng/theme@1.13.0`)
Реализация: `ds-analyzer/`

---

## 1. Зачем мы вообще что-то извлекаем

Конечная цель проекта — **анализатор продуктового кода, написанного на этом UI Kit**. Он должен отвечать на четыре вопроса:

| Вопрос | Что для этого нужно знать про кит |
|---|---|
| Какие компоненты кита используются и как часто? | Полный список публичных символов и их происхождение |
| Где в проекте захардкожены значения вместо токенов? | Обратный индекс `значение → токен` по цветам, размерам, шрифтам, теням |
| Где нарушены допустимые значения пропов? | Перечни вариантов (`view`, `size`) с точными ключами |
| Где переопределены стили кита или написаны кастомные компоненты? | Слоты (`classes`), обёртки над `@v-uik`, публичная граница API |

Ни на один из них нельзя ответить, парся кит «на лету» при каждом запуске:

1. **Дорого.** Кит — это lerna-монорепа с 61 директорией компонентов, 2192 токенами и ~1000 файлов. Полный разбор через ts-morph занимает ~1.4 с, разбор темы — ~0.2 с. Умножать это на каждый анализируемый проект бессмысленно.
2. **Хрупко.** Анализатор оказался бы связан с внутренней структурой кита. Смена `packages/theme/src/sys.ts` на другой формат ломала бы анализатор, а не экстрактор.
3. **Неверифицируемо.** Промежуточный артефакт можно провалидировать схемой, сравнить между версиями кита и закоммитить в git. Логику «внутри анализатора» — нет.

Поэтому вводится **промежуточное представление (IR)**: два JSON-файла, которые полностью описывают контракт дизайн-системы и версионируются вместе с ней.

```
ui-kit-eds-ce/            ds-analyzer/                    артефакты                 будущий анализатор
├── packages/theme  ──►  extract-tokens     ──►  artifacts/tokens.json      ──┐
└── packages/base   ──►  extract-components ──►  artifacts/components.json  ──┴──►  project-analyzer
```

## 2. Принципы, которым подчинены оба экстрактора

### 2.1 Артефакт валидирует сам себя

Каждый экстрактор проверяет свой результат zod-схемой **до записи на диск**. Артефакт, не удовлетворяющий контракту, — это баг экстрактора, и он не должен попасть к потребителю. Схема — единственный источник истины; TypeScript-типы выводятся из неё (`z.infer`), поэтому разъехаться они не могут.

### 2.2 Артефакты детерминированы

В `tokens.json` и `components.json` **нет временных меток**. Все коллекции отсортированы, сортировка — по код-юнитам (не `localeCompare`, который зависит от локали машины). Два запуска на одном ките дают побайтово одинаковый файл — это проверяется тестом. Метаданные запуска (время, длительности) вынесены в отдельный `extraction-summary.json`.

### 2.3 Пробелы фиксируются, а не замалчиваются

Кит не установлен (`node_modules` отсутствуют), поэтому типы из `@v-uik/*` недоступны. Везде, где из-за этого информация неполная, артефакт говорит об этом прямо:

* `meta.typeCheckerAvailable: false`
* `externalReExports[].resolved: false`
* `props[].extends` содержит неразрезолвленные базовые типы, а `members` честно пуст
* `diagnostics` содержит коды `external-reexport-unresolved`, `props-type-not-found`

Молча вернуть пустой список — худший из возможных исходов: потребитель решит, что у `Button` нет пропов.

### 2.4 Сохраняется происхождение, а не только результат

Для токенов хранится и «как написано» (`{edsRef.palette.pink.pink500}`), и «во что разрешилось» (`#ff1f78`). Первое нужно для правила «использован ref вместо sys», второе — для сопоставления с литералами в коде. Одно из другого не выводится.

### 2.5 Ноль зависимости от установленных зависимостей кита

Экстракторы работают на чистом клоне кита. Это проверено: `node_modules` в `ui-kit-eds-ce` отсутствуют, и всё работает.

## 3. Что извлекается

### 3.1 Токены → `artifacts/tokens.json`

Подробности: [extract-tokens.md](./extract-tokens.md)

| Раздел | Содержимое | Объём на текущем ките |
|---|---|---|
| `tokens[]` | Все токены трёх тиров с авторским и разрешённым значением по каждой теме | 2192 |
| `scales` | Шкалы радиусов, толщин, кеглей, интерлиньяжей, начертаний, гарнитур | 7 шкал |
| `reverseIndex` | `цвет → токены`, `px → токены`, `CSS-переменная → токен`, `литерал → токены` | по 2 темы |
| `diagnostics` | Находки о самом ките | 6 кодов |

### 3.2 Компоненты → `artifacts/components.json`

Подробности: [extract-components.md](./extract-components.md)

| Раздел | Содержимое | Объём на текущем ките |
|---|---|---|
| `components[]` | По директории: экспорты, React-компоненты, пропы, варианты, слоты, ассеты, обёрнутый `@v-uik` | 61 |
| `publicSymbols[]` | Плоский публичный API-срез | 462 |
| `barrel[]` | Дословное содержимое `components/index.ts` | ~90 записей |
| `externalReExports[]` | Пакеты, реэкспортированные целиком и не разрешимые | 25 |
| `diagnostics` | Находки и границы извлечения | 8 кодов |

### 3.3 Доступность кита → `artifacts/kit-a11y.json`

Подробности: [a11y.md](./a11y.md) §6

Появился позже первых двух и отличается от них в одном: собирается не из кита, а из
**`@v-uik`** — библиотеки, которую кит оборачивает у 58 из 61 компонента. Поведение, ради
которого компонент и рекомендуют — навигация стрелками, ловушка фокуса, связывание
`aria-controls` — в исходниках самого кита отсутствует.

| Раздел | Содержимое | Объём |
|---|---|---|
| `patterns[]` | по компоненту: роли, `aria-*`, обрабатываемые клавиши, работа с фокусом | 32 |
| `spacing` | фактическая шкала отступов и её сетка | 8 шагов, 4 вне сетки |
| `diagnostics` | находки о самом ките | 3 кода |

Два отличия от `tokens.json` и `components.json`, которые важно помнить:

* артефакт **необязателен** — без установленного `@v-uik` он пишется с
  `upstreamAvailable: false`, и зависящие от него правила заявляют об этом ограничением, а
  не молчат;
* он собран по **скомпилированному `dist/`**, поэтому это свидетельство, что что-то
  обрабатывается, а не доказательство, что обрабатывается верно.

## 4. Общая модель диагностик

Обе схемы используют один тип:

```ts
{
  code: string        // машиночитаемый идентификатор, напр. 'spacing-scale-missing'
  severity: 'info' | 'warning' | 'error'
  message: string     // человекочитаемое объяснение с последствиями
  samples: string[]   // до 10–15 примеров
  count: number       // истинное количество, даже если samples обрезаны
}
```

`samples` обрезается, `count` — нет. Это принципиально: артефакт, где написано «10 примеров», но не сказано, что их 300, вводит в заблуждение.

Диагностики описывают **дизайн-систему**, а не потребительский код. Они делятся на две группы:

* **дефекты кита** — `value-non-finite`, `reference-unresolved`, `css-variable-collision`, `comp-token-literal`;
* **границы извлечения** — `external-reexport-unresolved`, `props-type-not-found`, `component-entry-missing`.

Вторая группа так же важна, как первая: она сообщает будущему анализатору, каким участкам артефакта нельзя доверять как исчерпывающим.

## 5. Что даёт эта пара артефактов для детекции отклонений

| Правило анализатора | Опирается на |
|---|---|
| Хардкод цвета вместо токена | `reverseIndex.color[mode]`, поле `color.oklch` для перцептивной близости |
| Хардкод размера вне шкалы | `scales.borderRadiusPx`, `scales.fontSizePx`, `reverseIndex.dimensionPx` |
| Чужая гарнитура | `scales.fontFamilies` |
| Разъехавшийся типографический кортеж | `tokens[]` с `kind: fontSize / lineHeight / fontWeight / letterSpacing` |
| Использован ref вместо sys | `tokens[].tier` + `references[mode][].tier` |
| Значение пропа вне контракта | `components[].variants[].keys` |
| Переопределение стилей через `classes` | `components[].slots[].slots`, флаг `doc.inner` |
| Прямой импорт `@v-uik` в обход кита | `components[].wraps`, `externalReExports[].package` |
| Использование `_DNU_` или `@deprecated` | `publicSymbols[].deprecated`, диагностика `do-not-use-exported` |
| Калибровка детекторов на заведомо корректном коде | `components[].assets.stories` / `.examples` |

## 6. Известные ограничения текущей версии

1. **Символы из `@v-uik` не перечислены.** 25 пакетов реэкспортируются звёздочкой; без установленных зависимостей их экспорты неизвестны. `publicSymbols` — нижняя граница публичного API, а не точный список.
2. **Пропы частичны.** Из 132 найденных `*Props`-типов многие наследуют неразрешимые типы `@v-uik`; `members` содержит только то, что объявлено локально.
3. **Брейкпоинты отсутствуют.** `createCssVariables.ts` берёт их из `createTheme()` пакета `@v-uik/base`, а не из `@sds-eng/theme`.
4. **Нет шкалы отступов.** Это свойство самого кита, а не пропуск экстрактора — см. диагностику `spacing-scale-missing` и раздел 6 в [extract-tokens.md](./extract-tokens.md).
5. **Только `packages/base` и `packages/theme`.** Пакеты `data-grid`, `browser-tabs`, `rich-textarea`, `tree-dnd` в текущую версию не входят.

Все пять пунктов устраняются без изменения контрактов — схемы уже предусматривают соответствующие поля.

## 7. Как запускать

```bash
cd ds-analyzer
npm install

npm run extract              # оба экстрактора + extraction-summary.json
npm run extract:tokens       # только токены
npm run extract:components   # только компоненты

npm run verify               # typecheck + lint + tests
```

Путь к киту определяется в таком порядке: аргумент функции → переменная окружения `DS_UI_KIT_ROOT` → `../ui-kit-eds-ce`.
