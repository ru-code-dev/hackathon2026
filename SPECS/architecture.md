# Архитектура · DS-Analyzer

Как система устроена и почему именно так.

---

## 1. Общая схема

Два независимых конвейера, связанных только **артефактами знаний** — это осевая идея:
движок анализа не знает про конкретный кит ничего, кроме того, что записано в артефактах.

```
КОНВЕЙЕР ЗНАНИЙ (запускается при релизе кита)
┌──────────────┐   ┌───────────────────────────┐   ┌──────────────────────────────┐
│ чекаут кита  │──▶│ экстракторы (npm run       │──▶│ artifacts/*.json              │
│ ui-kit-eds-ce│   │ extract): tokens,          │   │ tokens · components · kit-a11y│
│              │   │ components, icons,         │   │ kit-icons · kit-signatures    │
│              │   │ kit-a11y, knowledge        │   │ kit-cards       (все @1)      │
└──────────────┘   └───────────────────────────┘   └──────────────┬───────────────┘
```

## 2. Стадии конвейера анализа

**B0 · Профиль** (`scanner/profile/`). Без установки зависимостей: обход с
gitignore-семантикой; алиасы из tsconfig/jsconfig, vite, webpack, package imports и
`ds.config.json`; принадлежность импорта киту — транзитивное замыкание его бочек
(re-export графа), поэтому `@sds-eng/base/Button` и алиас на него — один и тот же кит.

**B · Наблюдения** (`scanner/collectors/`). ts-morph в режиме
`useInMemoryFileSystem + noResolve` (парсинг без резолюции — быстро и без node_modules);
postcss/postcss-scss для стилей; двухпроходное разрешение SCSS-переменных с указанием
первопричины (deepest declaration); встроенный прогон eslint-plugin-jsx-a11y через
`Linter.verify` (без установки в проект). Результат — `observations@4`: элементы, объявления,
стилевые значения, импорты, обработчики, lint-сообщения. Всё нечитаемое — в `limitations`.

**C · Правила** (`rules/`). 26 чистых функций от `RuleContext` (наблюдения + спеки +
исходники для сниппетов). Финализация каждой находки: стабильный id от содержимого,
сниппет с `after` (замена одной строки → дифф всегда равнострочный), `impactKey`.
Ключевой инвариант сниппетов: «фантомная» пустая строка после завершающего `\n` файла
не считается строкой — иначе диффы у конца файла отвергаются `git apply`.

**Метрики** (`metrics/`). `usage.ts`: разбор рендеримых элементов по корзинам (сумма —
ровно total), токен-вердикты кастомов по их файлам и импортированным стилям;
`health.ts`: опубликованная формула.

**D · Рендер** (`report/`). Дашборд — предсобранный Vite-шаблон (`dashboard/dist`,
закоммичен); генерация отчёта = подстановка JSON-payload в `<script id="ds-data">` +
готовая подсветка Shiki (fine-grained core, **чисто-JS движок** — работает в бандле без
WASM и сети; инлайн-цвета сфолжены в классы — в разы меньше файл; подсветка кастомов
ограничена первыми 150, дальше — плоский текст, код не скрывается).

## 3. Контракты данных

Единственный источник типов — zod-схемы в `src/domain/`; TypeScript-типы выводятся из
них, артефакты валидируются на записи и чтении, контракт дашборда сверяется со схемами
отдельным тестом.

| Схема | Файл | Версия |
|---|---|---|
| Профиль проекта | `project-profile` | @1 |
| Наблюдения | `observations` | @4 |
| Находки/использование/сводка | `findings.json` · `usage.json` · `summary.json` | единый релиз |
| Знания о ките | `tokens` · `components` · `kit-a11y` · `kit-icons` · `kit-signatures` · `kit-cards` | @1 |
| Скиллы | `brief` · `patches` · `check` | @1 |

## 5. Скоринг кастомных компонентов (M5)

```
кандидат = argmax по 57 сигнатурам кита
score = 1 − Π(1 − wᵢ·sᵢ)        noisy-OR: признаки независимы,
                                 отсутствие данных не наказывает
признаки и веса:
  имя (нормализация шума My/App/V2… + словарь синонимов)  0.7
  ARIA (роли/атрибуты, generic-ARIA отброшены)            0.8
  пропы (Jaccard с TF-IDF-весами, минимум 2 общих)        1.0
  DOM-теги (generic-теги отброшены, дамп до min(1,n/2))   0.6
  CSS-свойства                                            0.3
  клон (MinHash-64, 3-шинглы, порог шума 0.5)             0.9

вердикты:  fork ─ клон ≥0.6 ИЛИ имя-в-имя + ≥75% API кита (≥3 пропов)
           custom ─ score ≥ 0.6      ambiguous ─ 0.3…0.6 → ИИ-этап
           novel ─ аналога нет, переиспользуется (≥3 использований, ≥2 файлов)
           duplicate ─ внутри проекта MinHash ≥ 0.8 (union-find, якорь — самый используемый)
```

Детерминизм: фиксированные сиды MinHash, никакого Math.random.

## 6. Diff-проверка (`check`)

Анализ всегда полный — правилам нужен глобальный контекст (частотные индексы,
переиспользование компонентов, кластеры дублей). Дифф входит после, как фильтр:
`git diff -U0` даёт точные добавленные строки (нулевой контекст = заголовок ханка
называет их сам), находка принадлежит диффу, если стоит на такой строке. Благодаря
детерминизму анализа это и есть «внесено этим диффом» — без второго прогона по базе.
Вердикт `check.json` (`ds-analyzer/check@1`) может гейтить CI (`--gate` → код 1 при
ошибках); в payload дашборда добавляется блок `diff` — экран открывается в режиме
«только изменения» с переключателем на весь проект (`all=1` в URL). stdout команды —
ровно один JSON; прогресс анализа уходит в stderr.

## 7. Поставка скиллов

`npm run build:skills` (esbuild):

- один ESM-файл `ds.mjs`: `--bundle --platform=node --format=esm --minify`; баннер даёт
  CJS-глобалы (`require` через `createRequire`, `__filename`/`__dirname`) — ts-morph,
  eslint и postcss живут в ESM-бандле; `jiti` (ленивая опциональная зависимость eslint)
  помечен external и никогда не исполняется;
- ассеты (артефакты + шаблон дашборда) кладутся рядом, скрипт находит их от собственного
  расположения — модель-исполнитель не передаёт путей;
- **ворота качества** (провал любого пункта = провал сборки): свежесть шаблона дашборда
  (mtime), дымовой тест на копии demo-app во временном git-репозитории без node_modules:
  analyze с обязательной подсветкой, brief с суммой долей 100, patches, deep-pack
  с шаблоном ответа, select-patch + настоящий `git apply`;
- после зелёного дымового теста сборка сама устанавливает скиллы локально через тот же
  `install-skills.sh`, которым пользуется пользователь (одна реализация установки).

## 8. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Кит-специфика вынесена в артефакты, движок кит-агностичен | переносимость на другие ДС (`add-new-ds-guide.md`); анализ не требует чекаута кита |
| Всё детерминировано (байт-в-байт, тест) | «здоровье» сравнимо между прогонами; отчёты можно диффать |
| ts-morph noResolve + in-memory FS | скорость и независимость от node_modules проекта |
| Спеки деградируют честно (`unavailable`) | нет артефакта → правила молчат и пишут limitation, а не падают |
| Единица дашборда — решение (`impactKey`) | сотни повторов одного решения не должны читаться как сотни проблем |
| Автофикс = равнострочная замена | ханки не смещают координаты друг друга; дифф собирается без бухгалтерии смещений |
| Диффы объединяются, конфликты показываются | «применил всё» не должно врать; skipped всегда виден |
| Дашборд = шаблон + подстановка payload | генерация отчёта без фронтенд-тулчейна на машине аудита |
| Shiki на чисто-JS движке | подсветка гарантирована в бандле; деградация запрещена сборкой |
| Сценарии скиллов рассчитаны на слабую модель | дословные команды, маркеры успеха, одна ветка ошибки, числа только из brief |
| Оракул размечен до реализации детекторов | правила подгоняются под истину, а не истина под правила |
| Diff-режим = полный анализ + фильтр, не инкрементальный анализ | глобальный контекст правил не режется; детерминизм делает пересечение честным «внесено диффом» |
