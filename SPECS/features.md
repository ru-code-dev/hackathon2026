# Каталог возможностей · DS-Analyzer

Полный перечень того, что система умеет, с механикой каждой возможности.

## 1. Детекторы: 32 вида находок

Обозначения: ⚙ — есть автофикс (готовый дифф), 🤖 — помечается `needsAgent` для ИИ-этапа.

### 1.1 Токены и стили

| Правило | Механика | |
|---|---|---|
| `token.literal.color` | литеральный цвет (hex/rgb/hsl/oklch/именованный) сравнивается со всеми токенами в OKLab с окном по альфе; вердикты: точно токен / почти / оттенок / чужой цвет; замена ранжируется по роли применения (`background` → фоновые sys-роли); точное совпадение без роли даёт ref-токен и помечается для ИИ | ⚙ 🤖 |
| `token.literal.dimension` | размер сравнивается со шкалами кита: на шкале / мимо шкалы / шкалы нет (магическое число — по частотному анализу проекта) | ⚙ |

### 1.3 Кастомные компоненты (M5)

Скоринг каждого локального компонента против 57 сигнатур кита; шесть независимых
признаков объединяются noisy-OR `1 − Π(1 − wᵢsᵢ)` — отсутствие данных не наказывает:

```
имя+синонимы w=0.7 · ARIA w=0.8 · пропы (TF-IDF-Jaccard) w=1.0
DOM-теги w=0.6 · CSS-свойства w=0.3 · клон по MinHash w=0.9
```

| Правило | Механика | |
|---|---|---|
| `component.custom` | score ≥ 0.6 — кит это уже умеет; кандидаты с причинами и барами | 🤖 |
| `component.ambiguous` | 0.3 ≤ score < 0.6 — похож, уверенности мало; главный клиент ИИ-этапа | 🤖 |
| `component.fork` | клон исходника кита (MinHash ≥ 0.6) или идентичное имя + ≥ 75 % API кита и ≥ 3 общих пропа | 🤖 |
| `component.novel` | аналога в ките нет, компонент переиспользуется (≥ 3 использований в ≥ 2 файлах) — кандидат в ДС | |
| `component.duplicate` | копии внутри проекта: MinHash ≥ 0.8, кластеризация union-find, якорь — самый используемый экземпляр | |

Анти-шумовая калибровка закреплена тестами: generic-теги и generic-ARIA не считаются,
один общий проп — не совпадение, клоновое сходство < 50 % — шум.

### 1.4 Иконки

Фингерпринт SVG: из разметки извлекаются path/базовые фигуры, числа округляются до 2
знаков, порядок и косметика (id, атрибуты экспорта) отбрасываются, хеш FNV-1a.
Работает и на JSX-разметке, не являющейся валидным XML. База — 233 иконки кита × 2 размера.

| Правило | Механика | |
|---|---|---|
| `icon.inline-svg` | инлайновый `<svg>` в JSX: совпал с иконкой кита → warning «замените на `<Имя>`», не совпал → candidate «кандидат в набор» | |
| `icon.foreign-file` | импорт `.svg`-файла или `url(*.svg)` в стилях мимо набора кита, с тем же двухуровневым вердиктом | |
| `icon.foreign-pack` | импорт из стороннего иконочного пакета (react-icons, lucide, mui-icons…) | |

### 1.5 Доступность

| Правило | Механика | |
|---|---|---|
| `a11y.focus.suppressed` | `outline: none`/`box-shadow: none` на интерактивном без замены индикатора | |
| `a11y.pattern.keyboard` | у виджета с ролью нет клавиатурных обработчиков, требуемых паттерном | |
| `a11y.pattern.focus` | диалог не закрывается по Escape / не управляет фокусом; распознаёт эквивалентную замену китом | |
| `a11y.pattern.relations` | `aria-labelledby`/`aria-controls`/`aria-describedby` указывает на несуществующий id | |
| `a11y.aria.invalid` | роль/атрибут вне ARIA 1.2; запрещённый или неподдерживаемый атрибут на роли | |
| `a11y.aria.required` | роль без обязательного состояния (switch без `aria-checked` и т. п.) | |
| `a11y.aria.redundant` | явная роль, дублирующая семантику тега | ⚙ |
| `a11y.name.missing` | контрол без доступного имени (текст, `aria-label`, связанный label) | |
| `a11y.contrast.text` | контраст по фактическим цветам (включая разрешённые SCSS-переменные) против WCAG 1.4.3/1.4.11 с учётом размера шрифта | |
| `a11y.lint` | 28 правил eslint-plugin-jsx-a11y, встроенных в сканер (без установки в проект) | частично ⚙ |

Каждая a11y-находка несёт: критерии WCAG, влияние на пользователя одним предложением
и совет `fix`; однозначные правки (положительный `tabIndex` → 0, лишний `autoFocus`,
избыточная роль…) идут готовым диффом.

## 2. Метрики

- **Здоровье 0–100**: `round(100 × (0.5 × (1 − min(1, Σвес/файлы/12)) + 0.3 × adoption +
  0.2 × tokenCoverage))`; веса: error 3 · warning 1 · info 0.25 · candidate 0. Формула
  публикуется в артефакте рядом с числом.
- **Состав интерфейса** (`elementBreakdown`): total = кит + кастомы(токены/смешанные/
  хардкод/без стилей) + внешние; у кита отдельно «без нарушений». Проценты для показа
  замыкаются ровно на 100 (метод наибольших остатков).
- **Покрытие токенами**: доля стилевых значений через `var(--токен)`.
- **Пробелы кита**: цвета, совпавшие с ref-токеном, но без sys-роли под применение.
- **Позитив**: что в проекте уже хорошо — отчёт из одних претензий читают один раз.

## 3. Дашборд (5 экранов, один HTML-файл)

| Экран | Возможности |
|---|---|
| **Сводка** | кольцо здоровья с формулой; 8 карточек-метрик (клик = переход с фильтром); «с чего начать» — топ решений по эффекту; категории; серьёзность с пояснениями; «что хорошо»; проблемные файлы; пробелы кита; «что не удалось проанализировать» |
| **План работ** | решения, отсортированные по эффекту (серьёзность × повторы); фасетные фильтры (категория/серьёзность/правило/автофикс); режим «Подряд»; чекбоксы отбора в PR; карточка решения: все вхождения, дифф, кандидаты со скорингом |
| **По файлам** | мастер-детейл; правки файла в порядке строк; «все авто-фиксы файла в PR» |
| **Дизайн-система** | кандидаты в ДС (novel/duplicate); кастомы: код с подсветкой, скоринг-кандидаты с причинами, токен-вердикты + фильтры-чипы; галерея «иконки мимо кита» (иконка отрисовывается из геометрии); палитра мимо токенов; размеры против шкал; топ токенов; матрица компонентов кита с реально используемыми вариантами; неиспользуемые и сторонние компоненты |
| **Доступность** | находки по правилам с советами и диффами; сводка «как проект звучит в скринридере»; раздел «Не проверено» — проверки, которые не отработали (пустой список ≠ чисто) |

Общее: всё по-русски; тёмная тема; навигация в URL (позиция переживает перезагрузку);
подсветка кода готовится при генерации (Shiki, чисто-JS движок; цвета сфолжены в классы —
файл в разы меньше); большие списки виртуализированы.

**PR-конвейер**: чекбоксы → один unified diff в браузере (равнострочные ханки; пересечения
объединяются; конфликты и невозможные правки показаны с причиной — ничего молча);
подсвеченный просмотр диффа; отправка в Jenkins generic-webhook-trigger; координаты
репозитория/ветки — из git-чекаута проекта (worktree и монорепо учтены); фолбэк —
готовая curl-команда.

## 4. Скиллы Qwen Code

| Скилл | Поток |
|---|---|
| `/ds-audit` | проверка среды → выбор цели (pwd / git clone по URL) через `ask_user_question` → `analyze` + `patches` + `brief` → отчёт по brief-JSON с кликабельными markdown-ссылками → «что дальше?» |
| `/ds-deep` | `deep-pack --top 5 \| --all` → пакеты ≤ 8k токенов (исходник + T1-карточки топ-3 кандидатов + T0-каталог + шаблон ответа) → вердикт «2 из 3 линз» (API · поведение · стили) по одному пакету за раз → `verdicts.md` → сводная таблица |
| `/ds-fix` | предполёт (git-репо? незакоммиченное?) → мультивыбор групп из `patches.json` → `select-patch` (один общий дифф) → ветка `ds-fix/<дата>` → `git apply --check` → коммит → пуш → PR: MCP → `gh` → Jenkins-вебхук → ссылка compare |

Подкоманды бандла `ds.mjs` (все печатают JSON в stdout, кроме analyze):

| Подкоманда | Вход → Выход |
|---|---|
| `analyze <dir>` | проект → `ui-analyzer/{dashboard.html, findings, usage, summary, profile}`; маркер успеха в stdout |
| `brief <dir>` | артефакты → компактный `ds-analyzer/brief@1` (≤ ~2 КБ): здоровье, итоги, доли (сумма 100), топ-10 проблем, топ-5 кастомов, счёт рекомендованных фиксов, пути |
| `patches <dir>` | findings → `patches.json` (`ds-analyzer/patches@1`): группы по impactKey с диффами, `recommended` (autoFixable ∧ confidence ≥ 0.9 ∧ ¬needsAgent), `recommendedKeys` |
| `deep-pack <dir> [--top N \| --all]` | usage+findings+kit-cards → `ui-analyzer/deep/<Компонент>.md` + JSON-список |
| `select-patch <dir> --keys a,b` | union выбранных групп → один дифф `ui-analyzer/selected.patch`; неизвестные ключи и пропуски — в ответе |

Установка: `./install.sh [--dir .my-fork]` из корня репозитория (или
`skills/install-skills.sh` из скопированной папки). Пересборка поставки:
`npm run build:skills` — включает дымовой тест (без него сборка не считается успешной).

## 5. Конфигурация

`ds.config.json` в корне анализируемого проекта (всё опционально):

```jsonc
{
  "kitPackages": ["@company/ds"],          // кит под другим именем
  "exclude": ["src/legacy/**"],            // синтаксис .gitignore
  "aliases": { "@app/*": ["src/*"] },      // если конфиги не разобрались
  "rules": { "token.literal.dimension": "off" },
  "ignoreFindings": ["f_abc123"],          // точечные исключения
  "ci": { "webhookUrl": "...", "repositoryUrl": "...", "targetBranch": "..." }
}
```

CLI-флаги `analyze`: `--kit-package`, `--exclude`, `--out`, `--artifacts`, `--no-dashboard`.
