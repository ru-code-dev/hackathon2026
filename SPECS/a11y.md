# A11y-слой: что реализовано и какие данные из него выходят

Версия: 1
Дата: 2026-07-28
Статус: логика готова, покрыта тестами, обкатана на трёх проектах. **UI не начат.**

Читателю этого документа: он написан для того, чтобы построить экран «Доступность», не читая исходники анализатора. Всё, что ниже, — факты из работающего кода и реальных артефактов, а не план.

Связанные: [`architecture.md`](./architecture.md) · [`a11y-research.md`](./a11y-research.md) (исследование, почему сделано именно так)

---

## 1. Одним абзацем

Анализатор ищет отклонения от дизайн-системы. A11y-слой добавляет к этому доступность — **как грань существующих сущностей, а не как параллельную ветку**. Появились: новая категория находки `a11y`, новое поле `a11y` на каждой находке, новый артефакт `kit-a11y.json` и новый код ограничения `spec-unavailable`. Ничего в существующих контрактах не сломано.

Всего **39 проверок доступности**: 9 своих правил плюс 30 правил канонического `eslint-plugin-jsx-a11y`, обёрнутых десятым правилом.

## 2. Где лежат данные

```
ds-analyzer/artifacts/kit-a11y.json    ← что умеет сам кит (§6)
<project>/ui-analyzer/findings.json    ← findings[] с category='a11y' и полем a11y (§4)
<project>/ui-analyzer/summary.json     ← findings.byCategory.a11y + limitations[] (§7)
```

Дашборд получает `findings.json` и `summary.json` внутри `window.__DS_DATA__`, как обычно.
**`kit-a11y.json` в payload пока не попадает** — если экрану нужна матрица «что умеет кит», её надо добавить в `src/report/render.ts`.

## 3. Реестр правил

### 3.1 Свои девять

| Правило | Severity | subkind | WCAG | `expected` | `needsAgent` |
|---|---|---|---|---|---|
| `a11y.focus.suppressed` | error | `blanket` · `onFocus` | 2.4.7 | — | нет |
| `a11y.pattern.keyboard` | error · warning | `noHandler` · `handlerUnreadable` | 2.1.1 | **компонент кита** | да |
| `a11y.pattern.focus` | error | `noEscape` · `noFocusTrap` | 2.1.2 · 2.4.3 | **компонент кита** | да |
| `a11y.pattern.relations` | error · warning | `danglingId` · `unmatchedExpression` | 1.3.1 · 4.1.2 | — | частично |
| `a11y.aria.invalid` | error · warning | `unknownRole` · `abstractRole` · `unknownAttribute` · `unsupportedAttribute` · `prohibitedAttribute` | 4.1.2 | — | нет |
| `a11y.aria.required` | error | имя роли (`checkbox`, `slider`, …) | 4.1.2 | — | нет |
| `a11y.aria.redundant` | info | `null` | — | тег без роли | нет |
| `a11y.name.missing` | error | `iconOnly` · `unlabelled` | 4.1.2 | — | да |
| `a11y.contrast.text` | error · warning | `normalText` · `largeText` | 1.4.3 | — | нет |

### 3.2 Десятое — `a11y.lint`

Обёртка над `eslint-plugin-jsx-a11y`. **`subkind` — это имя правила плагина**, по нему же ищется его документация. На реальном проекте это 60–90 % всех a11y-находок, поэтому **дашборд обязан группировать по `subkind`**, иначе экран превратится в 58 одинаковых строк.

Запускаются 30 правил:

```
alt-text · anchor-ambiguous-text · anchor-has-content · anchor-is-valid
aria-activedescendant-has-tabindex · aria-proptypes · autocomplete-valid
click-events-have-key-events · heading-has-content · html-has-lang · iframe-has-title
img-redundant-alt · interactive-supports-focus · label-has-associated-control · lang
media-has-caption · mouse-events-have-key-events · no-access-key
no-aria-hidden-on-focusable · no-autofocus · no-distracting-elements
no-interactive-element-to-noninteractive-role · no-noninteractive-element-interactions
no-noninteractive-element-to-interactive-role · no-noninteractive-tabindex
no-redundant-roles · no-static-element-interactions · prefer-tag-over-role
scope · tabindex-no-positive
```

Не запускаются: 3 устаревших (`accessible-emoji`, `label-has-for`, `no-onchange`) и 6, которые наши правила решают точнее, зная про кит (`aria-props`, `aria-role`, `aria-unsupported-elements`, `role-has-required-aria-props`, `role-supports-aria-props`, `control-has-associated-label`).

**Severity назначаем мы, а не линтер.** `alt-text` — `error`, `click-events-have-key-events` — `warning`, `prefer-tag-over-role` — `info`. Правило, появившееся после обновления плагина и ещё не классифицированное, всё равно попадает в отчёт — `info` без критерия WCAG.

## 4. Форма находки

Обычная `Finding` плюс одно поле:

```ts
a11y: {
  wcag: string[]          // ['2.1.1'] — критерии; [] когда критерий не применим
  pattern: string | null  // 'tablist', 'dialog-modal' — роль или паттерн; null вне паттернов
  impact: string          // одна фраза: что теряет пользователь. Никогда не пустая
} | null
```

`null` на всех находках вне a11y-правил. Поле **всегда присутствует** явным `null` — артефакт коммитится и диффится, форма должна быть стабильной.

Реальная находка целиком:

```jsonc
{
  "id": "f_0072",
  "rule": "a11y.pattern.keyboard",
  "subkind": "noHandler",
  "category": "a11y",
  "severity": "error",
  "confidence": 0.95,
  "file": "src/features/settings/SettingsTabs.tsx",
  "line": 23,
  "column": 5,
  "snippet": { "before": "…", "after": null, "highlightLine": 5, "startLine": 19 },
  "actual": "role=\"tablist\"",
  "expected": { "token": null, "cssVar": null, "component": "Tabs", "value": "<Tabs …>" },
  "why": "Элемент объявляет role=\"tablist\", но не обрабатывает ни одной клавиши. …",
  "note": null,
  "rootCause": null,
  "appliedTo": null,
  "a11y": {
    "wcag": ["2.1.1"],
    "pattern": "tablist",
    "impact": "Виджет tablist недоступен с клавиатуры: фокус в него попадает, но управлять им нечем."
  },
  "autoFixable": false,
  "needsAgent": true,
  "candidates": [
    { "component": "BrowserTabs", "score": 0.9,
      "reasons": ["рендерит role=\"tablist\"", "обрабатывает ArrowDown, ArrowLeft, ArrowRight, ArrowUp", "управляет фокусом"] }
  ],
  "impact": { "occurrences": 1, "files": 1 },
  "impactKey": "a11y.pattern.keyboard:tablist"
}
```

### Что показывать крупно

`a11y.impact` — последствие для человека, а не пересказ правила. Это заголовок карточки. `why` — мелким, это объяснение.

`expected.component` заполнен у `pattern.keyboard` и `pattern.focus` и содержит **уже выбранный канонический компонент** — `Tabs`, а не `BrowserTabs`; `Modal`, а не `DatePicker`. Выбор сделан в `A11ySpec.canonicalComponentFor()`, дашборду ранжировать не нужно.

`candidates[].reasons` — человекочитаемые, готовы к показу как есть.

`note` заполнен там, где у правила есть известная слепая зона (§8). **Показывать рядом с `why`, не прятать.**

## 5. Категория и сводка

`'a11y'` добавлена в `findingCategorySchema` и в `summary.findings.byCategory`. Реальный `summary.json` demo-app:

```json
{"token":83,"typography":1,"font":4,"api":7,"override":5,"component":10,"icon":2,"a11y":6}
```

Агрегата по WCAG в `summary` **нет** — считается на клиенте по `findings[].a11y.wcag`, их немного.

Отдельной оси «A11y» в `healthScore` нет: a11y-находки входят в общий счёт по severity.

## 6. `kit-a11y.json` — что умеет сам кит

Собирается из установленного `@v-uik`: `npm run extract:kit-a11y`.

```jsonc
{
  "$schema": "ds-analyzer/kit-a11y@1",
  "meta": { "upstreamVersion": "1.23.0", "packagesScanned": 63, "upstreamAvailable": true },
  "patterns": [{
    "component": "Tabs",
    "packages": ["@v-uik/tabs"],
    "matchedBy": "wraps",              // 'wraps' | 'name'
    "roles": ["tab", "tablist"],
    "ariaAttributes": ["aria-selected", "aria-controls", "aria-orientation"],
    "keysHandled": ["ArrowDown", "ArrowLeft", "ArrowRight", "ArrowUp"],
    "managesFocus": true
  }],
  "spacing": {
    "steps": [{ "px": 0, "occurrences": 99 }],
    "offGridSteps": [{ "px": 2, "occurrences": 8 }],
    "totalDeclarations": 281, "coverage": 0.97,
    "gridBase": 4, "gridCoverage": 0.907
  },
  "diagnostics": [{ "code": "…", "severity": "info", "message": "…", "samples": [], "count": 0 }]
}
```

Текущие цифры: **32 компонента** с a11y-признаками, из них 16 найдены по `wraps` и 16 — по имени. Шкала отступов **0/4/8/12/16/20/24/32**, вне сетки — 2/6/10/15.

Диагностики: `spacing-scale-derived`, `kit-widget-without-keyboard-evidence`, `upstream-not-installed`.

**Две вещи, которые UI обязан подавать как неточные:**

* `matchedBy: "name"` — догадка. 34 компонента кита импортируют через бочку `@v-uik/base` и своего пакета не называют; связь восстановлена по имени. Наименование один-к-одному, но это эвристика.
* `spacing` — шкала, которой кит **следует**, а не публикует. Тира spacing в теме нет вовсе. Отклонение от неё стоит `info`, в отличие от опубликованной шкалы радиусов.

Одну роль могут рендерить несколько компонентов: `dialog` → `DatePicker`, `Modal`, `TimePicker`. Для показа пользователю берите `canonicalComponentFor`, а не первый по алфавиту.

## 7. Отличать «чисто» от «не проверено»

Самое важное для UI, и самое лёгкое сделать неправильно.

Пустой список a11y-находок означает **одно из двух**. Правила, которые не смогли отработать, заявляют об этом через `summary.limitations[]`:

| `reason` | Когда | Что не проверено |
|---|---|---|
| `spec-unavailable` | нет `kit-a11y.json` (не установлен `@v-uik`) | клавиатурная доступность **всех** виджетов |
| `unsupported-syntax` | `outline: none` в объектном стиле (JSS) | нарисована ли замена фокуса |
| `dynamic-styles` | значение из выражения | стилевые правила на этой строке |
| `parse-error` | файл не разобран | всё в этом файле |

```jsonc
{
  "file": "src/features/settings/SettingsTabs.tsx",
  "line": 23,
  "reason": "spec-unavailable",
  "detail": "Клавиатурная доступность виджета не проверена: артефакт kit-a11y.json не собран…"
}
```

**Требование к UI:** если в `limitations[]` есть хоть один `spec-unavailable`, шапка раздела «Доступность» обязана сказать, что проверка неполная. Пустой список находок рядом с молчаливой лимитацией читается как «здесь чисто» — это ложь, и она хуже, чем отсутствие раздела.

## 8. Границы правил

Формулировки в интерфейсе не должны быть сильнее проверенного. Каждая строка уже отражена в `note` соответствующей находки.

| Правило | Не видит |
|---|---|
| `pattern.keyboard` | `role={expr}` — только литеральные роли; паттерн, размазанный по файлам |
| `pattern.focus` | фокус, перенесённый через внешний хук; признаки читаются синтаксически |
| `pattern.relations` | целевой элемент в другом файле |
| `name.missing` | текст из выражения и дочерний компонент → вердикт «недоказуемо», правило молчит |
| `contrast.text` | унаследованный фон; пара считается, только если `color` и `background` в одном блоке |
| `aria.invalid` | роль на кастомном компоненте — она неизвестна |
| `focus.suppressed` | объектные стили: вложенность схлопывается при сборе |
| всё | порядок фокуса, экранные дикторы, зум — статически неразрешимо |

**Почему 39, а не 100.** Оставшиеся правила `axe-core` требуют отрендеренного DOM: контраст с учётом реальной раскладки, уникальность лендмарков, порядок заголовков на странице. Из статики они недостижимы в принципе. Из реально пропущенного статического — дубли `id` и структура таблиц, это 2–3 правила.

## 9. Чего в данных нет

1. **`kit-a11y.json` не в payload дашборда** — нужна правка `src/report/render.ts`.
2. **Нет `byWcag`** в `summary` — считать на клиенте.
3. **Нет контраста токенов кита.** Движок (`src/a11y/contrast.ts`, 16 тестов) готов; правило считает только пары из кода проекта. Аудит comp-токенов (`colorText*` × `colorBackground*`) не написан.
4. **Нет отделения демо-кода.** Находки в `__tests__`, `examples/`, `*.stories.tsx` смешаны с продуктовыми: на ките это 134 из 175. Свойство сканера, общее для всех правил.
5. **Нет отдельной оси «A11y»** в health score.
6. **APG не извлечён** — контракт паттернов это 11 ролей в коде `pattern-keyboard.ts` плюс данные `aria-query`.

## 10. Что было изменено в общих контрактах

Для ревью другим агентом.

| Файл | Изменение |
|---|---|
| `domain/findings.ts` | `'a11y'` в `findingCategorySchema`; `a11ySchema`; поле `a11y` на `findingSchema` |
| `domain/observations.ts` | `@1` → **`@5`**: `propExpressions`, `eventHandlers`, `keysHandled`, `content`, `hasLabelAncestor`, `lintMessages`; агрегация обработчиков на `Declaration` |
| `domain/profile.ts` | код `spec-unavailable` в `limitationReasonSchema` |
| `rules/types.ts` | `RuleContext.a11y`; необязательный `Rule.limitations()`; `RawFinding.a11y` |
| `rules/index.ts` | 10 правил в реестре; `collectRuleLimitations()` |
| `metrics/health.ts` | `ALL_CATEGORIES` / `ALL_SEVERITIES` выводятся из схемы, а не захардкожены |
| `dashboard/src/contract.ts` | **новый**: типы вынесены из `data.ts`, чтобы анализатор мог их проверить без DOM |
| `scanner/scan.ts` | вызов линтера, `lintMessages` в наблюдениях |

Новые зависимости: `aria-query` (MIT, модель ARIA 1.2), `eslint` + `eslint-plugin-jsx-a11y` (MIT).

**Про бандл.** Проверено сборкой: собирается в один файл ~41 МБ, но только в CJS и с тремя правками — `--external:jiti`, убрать top-level `await` в CLI, дать `analyzerRoot` фолбэк вместо `import.meta.url`. ESM невозможен из-за динамического `require` в `ts-morph`. 23 МБ из 41 — это `typescript`, вклад eslint-стека ~12 МБ.

### Где это шатко — читать перед тем, как обещать точность

30 правил плагина стабильны: это эталонная реализация, отслеживающая спеку.

**Риск в наших девяти.** Три из них давали ложные срабатывания, и **все три нашлись только прогоном на реальном коде, а не тестами**:

* `name.missing` — 11 ложных из 11 на дашборде (текст внутри вложенного элемента, обёртка `<label>`)
* `focus.suppressed` — 9 ложных на ките (фокус оформлен классом `&$focused`, а не псевдоклассом)
* `pattern.relations` — 9 ложных на ките (id передан пропом внутрь компонента)

Все починены, на каждую есть регрессионный тест. Закономерность важнее самих багов: **юнит-тесты не поймали ни одного**.

Ground truth для a11y тонкий: 5 ожиданий из 113 в оракуле. Цифра «precision ≥ 0.95» посчитана в основном на токенных правилах и для a11y статистически ничего не значит.

Вне этого репозитория не запускалось.

## 12. Воспроизвести

```bash
cd ds-analyzer
npm run extract:kit-a11y                    # нужен установленный @v-uik
npx tsx src/cli/analyze.ts ../demo-app      # → ui-analyzer/{findings,summary,usage}.json
```

`@v-uik` ставится из корпоративного реестра и требует scoped-конфига:

```
# ui-kit-eds-ce/.vuik/.npmrc
@v-uik:registry=https://gitverse.ru/api/packages/sbertech/npm/
```

Анализатор ищет апстрим в `<kit>/node_modules/@v-uik`, затем в `<kit>/.vuik/node_modules/@v-uik`. Без него всё работает, но `kit-a11y.json` пишется с `upstreamAvailable: false`, а `pattern.keyboard` молчит и заявляет об этом лимитацией.
