# DS-Analyzer — аудит соответствия дизайн-системе `sds-eng`

Статический анализатор React/TypeScript-проектов: находит **все** отклонения от дизайн-системы —
токены, компоненты, импорты, иконки, доступность — и превращает их в план работ с готовыми
диффами, одностраничный дашборд и pull request в один клик. Поверх — скиллы для Qwen Code:
аудит, ИИ-разбор кастомных компонентов и автофиксы голосом «запусти скилл ds-audit».

Ничего не требует установки в анализируемом проекте: ни зависимостей, ни сборки, ни сети.

```
продуктовый проект ──▶ анализатор ──▶ ui-analyzer/
   (как есть, без           │            ├── dashboard.html   ← один файл, открыть двойным кликом
    npm install)            │            ├── findings.json    ← каждая находка с диффом и «почему»
                            │            ├── usage.json       ← состав интерфейса, кастомы, токены
                            │            ├── summary.json     ← здоровье, метрики, ограничения
                            │            └── patches.json     ← готовые git-диффы по группам
                            │
             знания о ките (artifacts/*.json, извлечены
             автоматически из исходников ui-kit-eds-ce)
```

## Что находит анализатор

33 вида отклонений в шести категориях. Каждая находка несёт: точное место (файл:строка),
фрагмент кода, объяснение «почему это проблема», уверенность 0–1, а где возможно — готовую
замену и дифф.

### Токены и стили

| Правило | Что ловит |
|---|---|
| `token.literal.color` | Цвет литералом (`#1a1a1a`, `rgb()`, `oklch()`…) вместо токена. Матчинг в OKLab: «точно токен / почти / оттенок / чужой цвет», ранжирование по роли применения (background → фоновая роль) |
| `token.literal.dimension` | Размер литералом вместо токена: значение есть на шкале / мимо шкалы / шкалы нет — магическое число |
| `token.typography.partial` | Типографика набрана вручную вместо готового стиля кита |
| `token.tier.violation` | `ref`-переменная напрямую вместо семантической `sys`-роли |
| `font.foreign` | Гарнитура не из кита |
| `style.override.repaint` | Перекраска компонента кита снаружи |
| `style.override.size` | Изменение внутренних отступов компонента кита |
| `style.override.inner` | Стилизация приватного (`@inner`) слота |
| `style.override.important` | `!important` поверх стилей кита |

### API кита

| Правило | Что ловит |
|---|---|
| `import.bypass` | Импорт в обход публичного пакета кита |
| `import.internal` | Импорт внутренним путём (`/dist/…`, глубокие пути) |
| `api.dnu` | Импорт запрещённого («do not use») модуля |
| `prop.invalid` | Несуществующее значение пропа (проверяется по извлечённым вариантам) |
| `api.deprecated` | Устаревший API кита |

### Кастомные компоненты (детектор M5)

Скоринг по шести независимым признакам (имя + синонимы, ARIA, пропы с TF-IDF-весами,
DOM-теги, CSS-свойства, клон по MinHash) с комбинацией noisy-OR — отсутствие данных никогда
не наказывает.

| Правило | Что ловит |
|---|---|
| `component.custom` | Компонент, который кит уже умеет — с кандидатами и причинами («совпало имя, 4 пропа, роль dialog») |
| `component.fork` | Разошедшаяся копия компонента кита (клон по AST или идентичное имя + ≥75 % API) |
| `component.ambiguous` | Похож на компонент кита, но уверенности мало — отдаётся ИИ-этапу |
| `component.novel` | Переиспользуемый компонент, которого в ките нет — кандидат в дизайн-систему |
| `component.duplicate` | Один и тот же компонент скопирован внутри проекта (union-find по MinHash ≥ 0.8) |

### Иконки

Геометрический фингерпринт SVG (нормализованные path-данные, устойчив к шуму экспорта —
id, порядок атрибутов, точность координат) против 233 иконок кита.

| Правило | Что ловит |
|---|---|
| `icon.inline-svg` | Инлайновый `<svg>` в JSX: совпал с иконкой кита → «замените на неё», не совпал → кандидат в набор |
| `icon.foreign-file` | `.svg`-файл импортом или `url()` в стилях мимо набора кита |
| `icon.foreign-pack` | Сторонний пакет иконок (`react-icons`, `lucide` и т. п.) |

### Доступность

| Правило | Что ловит |
|---|---|
| `a11y.focus.suppressed` | Кольцо фокуса убрано без замены |
| `a11y.pattern.keyboard` | Виджет с ролью недоступен с клавиатуры |
| `a11y.pattern.focus` | Диалог не удерживает или не возвращает фокус |
| `a11y.pattern.relations` | ARIA-связь (`aria-labelledby`…) ведёт в никуда |
| `a11y.aria.invalid` | Несуществующая роль или ARIA-атрибут, запрещённый или неподдерживаемый атрибут на роли |
| `a11y.aria.required` | Роль без обязательного состояния (`switch` без `aria-checked`) |
| `a11y.aria.redundant` | Роль дублирует семантику тега |
| `a11y.name.missing` | Контрол без доступного имени |
| `a11y.contrast.text` | Текст не набирает контраст WCAG (вычисляется по фактическим цветам, включая SCSS-переменные) |
| `a11y.lint` | Базовые правила eslint-plugin-jsx-a11y (28 проверок), встроенные без установки |

На каждой a11y-находке — влияние на пользователя, критерий WCAG и совет «что делать»;
однозначные правки (положительный `tabIndex`, `autoFocus` и др.) идут готовым диффом.

### Метрики

- **Здоровье проекта 0–100** — формула опубликована рядом с числом:
  `50 % чистота · 30 % внедрение кита · 20 % покрытие токенами`.
- **Состав интерфейса** — каждый рендеримый компонент ровно в одной корзине, сумма всегда 100 %:
  из ДС (и «из них без нарушений») · кастомные на токенах · смешанные · на хардкоде ·
  без стилей · внешние. Проценты замыкаются на 100 методом наибольших остатков.
- **Токен-вердикт каждого кастома**: «на токенах ДС / токены + хардкод / хардкод / без стилей».
- **Пробелы кита** — цвета, у которых нет sys-роли под применение: вход для команды ДС.
- **Честные ограничения** — всё, что не удалось проанализировать, перечислено поимённо;
  молчаливый пропуск читался бы как «здесь чисто».

## Дашборд

Один самодостаточный HTML-файл (без сети, без CDN), тёмная тема, весь по-русски.
Единица работы — **решение**: находки группируются по `impactKey` («одно решение чинит все
повторы»). Пять экранов:

- **Сводка** — вердикт: кольцо здоровья + 8 карточек (отклонения, решения, авто-фикс,
  компоненты из ДС, кастомные на токенах, кастомные без токенов, покрытие токенами,
  доступность), «с чего начать» по эффекту, категории, серьёзность, «что хорошо»,
  проблемные файлы, пробелы кита.
- **План работ** — решения по приоритету (серьёзность × повторы), фасетные фильтры,
  режим «Подряд», чекбоксы для отбора автофиксов в PR.
- **По файлам** — мастер-детейл: правки файла в порядке строк, «все авто-фиксы файла в PR».
- **Дизайн-система** — взгляд со стороны кита: кандидаты в ДС, кастомы с кодом,
  скоринг-кандидатами и токен-вердиктами (фильтры-чипы), галерея «иконки мимо кита»
  с отрисовкой из геометрии, палитра мимо токенов, размеры против шкал, топ токенов,
  матрица компонентов кита.
- **Доступность** — все a11y-находки с советами и диффами, сводка «как проект звучит
  в скринридере» и раздел «Не проверено»: пустой список — не то же самое, что «чисто».

**PR-конвейер**: отметить правки чекбоксами → в браузере собирается один unified diff
(подсвеченный; пересечения объединяются, конфликты показываются, ничего не выбрасывается
молча; формат проверен `git apply`) → отправка в Jenkins generic-webhook-trigger →
pull request. Репозиторий и целевая ветка определяются из git-чекаута проекта автоматически;
при CORS-блокировке — готовая curl-команда.

Код всюду подсвечен (Shiki, движок на чистом JS — работает и в бандле без WASM и сети).

## Скиллы для Qwen Code

Сценарии на русском для модели-исполнителя + **один самодостаточный бандл** `ds.mjs`
(esbuild, ~14 МБ, ноль зависимостей). Пользователю нужны только **Node ≥ 20 и git**.

- **`/ds-audit`** — «какой проект анализируем?» (текущий каталог или git-URL — склонирует
  сам) → анализ → отчёт по компактному brief-JSON (модель ничего не пересчитывает — доли
  уже замкнуты на 100 %) → ссылка на дашборд → «что дальше?».
- **`/ds-deep`** — ИИ-разбор кастомных компонентов: на каждый собирается пакет ≤ 8k токенов
  (исходник + карточки кандидатов из кита + каталог T0 + шаблон ответа); вердикт по правилу
  «2 из 3 линз» (API · поведение · стили) → `verdicts.md`.
- **`/ds-fix`** — мультивыбор групп правок → один общий дифф → новая ветка →
  `git apply --check` → коммит → пуш → Pull Request (MCP системы контроля версий →
  `gh` → Jenkins-вебхук → ссылка compare).

Сборка не считается успешной без **дымового теста**: копия demo-app во временном
git-репозитории без node_modules, все подкоманды через бандл, обязательная подсветка кода
в дашборде и реальный `git apply` собранного патча.

## Установка и запуск

### Анализатор (разработчику)

```bash
cd ds-analyzer
npm install
npm run analyze -- /path/to/your-project
# → /path/to/your-project/ui-analyzer/dashboard.html  — открыть двойным кликом
```

| Флаг | Зачем |
|---|---|
| `--kit-package @company/ds` | кит опубликован под своим именем |
| `--exclude 'src/legacy/**'` | добавить исключения (синтаксис .gitignore) |
| `--out <dir>` | писать отчёт не в проект |
| `--artifacts <dir>` | другая версия спеки кита (другая дизайн-система) |
| `--no-dashboard` | только JSON |

Тонкая настройка в проекте — `ds.config.json`: `kitPackages`, `exclude`, `aliases`,
`rules: {"<id>": "off"}`, `ignoreFindings`, координаты CI для PR.

### Скиллы Qwen Code (пользователю) — без npm и сборки

Готовая папка `skills/` уже собрана и закоммичена в корне репозитория:

```bash
git clone git@github.com:ru-code-dev/hackathon2026.git
cd hackathon2026
./install.sh                         # форк Qwen со своим каталогом: ./install.sh --dir .my-fork
# перезапустить Qwen Code → /ds-audit
```

Установка — чистое копирование в `~/.qwen/skills` (или `~/<ваш-каталог>/skills`; пути внутри
сценариев переписываются автоматически). Нужны только **Node ≥ 20 и git**.

Разработчику: `cd ds-analyzer && npm run build:skills` — пересобирает `skills/`,
прогоняет дымовой тест и переустанавливает локально.

### Обновление знаний о ките

```bash
npm run extract                 # нужен чекаут ui-kit-eds-ce рядом (или DS_UI_KIT_ROOT)
```

Извлекает всё автоматически: 2192 токена, 61 компонент, 233 иконки, ARIA-паттерны,
сигнатуры и карточки. Ничего рукописного. Другие дизайн-системы — см.
`SPECS/add-new-ds-guide.md`.

## Качество

- Оракул: рукописная разметка **до** реализации детекторов; precision/recall
  **1.000/1.000** на 105 ожиданиях стадии правил и 9 ожиданиях детектора кастомов.
- **0** ложных срабатываний API-правил на 684 канонических примерах самого кита.
- Два прогона анализатора **байт-в-байт идентичны** (закреплено тестом).
- `npm run verify` — typecheck + lint + 785 тестов.
- Каждый пойманный false positive скоринга закреплён отдельным юнит-тестом.
