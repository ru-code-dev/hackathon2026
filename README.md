# ds-analyzer

Находит отклонения от дизайн-системы `sds-eng` в любом React/TypeScript-проекте и объясняет каждое: что написано, чем это должно было быть и что сломается, если не чинить.

Результат — один HTML-файл, который открывается двойным кликом. Без сервера, без сети.

---

## Запуск

```bash
git clone git@github.com:ru-code-dev/hackathon2026.git
cd hackathon2026/ds-analyzer
npm install

npm run analyze -- /путь/к/вашему/проекту
```

Всё. Отчёт лежит в `/путь/к/вашему/проекту/ui-analyzer/dashboard.html` — откройте его двойным кликом.

```
  my-product · health 49/100 · 0.25s

  Adoption        76%
  Token coverage  4%
  Чистых файлов   9 из 24
  Отклонений      98  (30 error · 45 warning · 23 info)
  Авто-фиксится   30

    token.literal.dimension      50
    token.literal.color          30
    font.foreign                  4

  → /путь/к/вашему/проекту/ui-analyzer
  → /путь/к/вашему/проекту/ui-analyzer/dashboard.html  ← откройте двойным кликом
```

### Чего НЕ нужно

* **Чекаута самого кита.** Спека уже извлечена и лежит в `ds-analyzer/artifacts/`.
* **Установленных зависимостей анализируемого проекта.** Разбор чисто синтаксический, `node_modules` не нужны.
* **Сборки фронтенда на вашей машине.** Шаблон дашборда собран и закоммичен.
* **Чтобы проект собирался.** Ошибка типов не мешает разобрать AST.

Нужен только Node ≥ 20.

## Флаги

| Флаг | Когда нужен |
|---|---|
| `--kit-package @company/design-system` | кит опубликован у вас под другим именем |
| `--exclude 'src/legacy/**'` | добавить исключения, синтаксис `.gitignore`, можно повторять |
| `--out <dir>` | писать отчёт не внутрь проекта |
| `--no-dashboard` | только JSON, без HTML |
| `--artifacts <dir>` | другая версия спеки кита |

Можно указать не весь проект, а папку или один файл:

```bash
npm run analyze -- /путь/к/проекту/src/features/orders
npm run analyze -- /путь/к/проекту/src/shared/ui/Button.tsx
```

Корень, `tsconfig` и алиасы всё равно ищутся от корня репозитория — иначе алиас не разрешится, и находка молча пропадёт.

## Что появится в `ui-analyzer/`

| Файл | Что внутри |
|---|---|
| **`dashboard.html`** | отчёт, открыть двойным кликом |
| `findings.json` | все отклонения: правило, координаты, объяснение, замена, дифф |
| `usage.json` | статистика по компонентам кита и распределение вариантов |
| `summary.json` | health score, метрики, «что хорошо», пробелы кита, ограничения |
| `project-profile.json` | что сканер понял про проект: корень, алиасы, откуда берётся кит |
| `.cache/observations.json` | сырые наблюдения до всяких суждений |

### Дашборд

Четыре экрана, всё по-русски, всё кликабельно, ничего не тупиковое. Единица отчёта — не находка, а **решение**: один цвет, повторённый 200 раз, — это одна карточка «замени на токен, закроет 200 вхождений в 30 файлах».

**Сводка** — кольцо здоровья с опубликованной формулой; метрики (отклонения, решения, авто-фикс, внедрение кита, покрытие токенами) — каждая с расшифровкой «из чего посчитано» и кликом в план; «С чего начать» — топ решений по эффекту; чарты по категориям и серьёзности; «Что хорошо»; проблемные файлы; «Пробелы кита»; честный список того, что не удалось проанализировать.

**План работ** — решения, отсортированные по эффекту (вес серьёзности × повторы). Карточка раскрывается: объяснение, корень (SCSS-переменная — «чини здесь»), вхождения, сгруппированные по файлам, каждая строка — в дифф с посимвольной подсветкой и кнопками копирования. Фасетные фильтры показывают счётчик до клика — пустой список без объяснения невозможен. Режим «Подряд» — виртуализованная лента всех вхождений для тех, кому нужна каждая строка.

**По файлам** — мастер-детейл: слева файлы по суммарному весу, справа правки выбранного файла в порядке строк — план правок для файла, открытого рядом в редакторе.

**Дизайн-система** — взгляд со стороны кита: кастомные компоненты с их кодом и вердиктом (похож на кит → проверить на дубль · переиспользуется без пары в ките → кандидат в дизайн-систему), палитра мимо токенов, размеры против шкалы, топ используемых токенов, матрица компонентов кита с реально нужными вариантами, сторонние и неиспользуемые компоненты. Точный скоринг похожести и код замены появятся на этапе M5 (ИИ) — до этого совпадение по имени честно подписано как эвристика.

Состояние целиком в URL — ссылкой можно делиться. Любой переход сбрасывает старые фильтры; активные всегда видны чипами. Клавиши `1`–`4`, `/` — поиск, `Esc` — сбросить фильтры.

Размер: ~990 КБ шаблона + ~3 КБ на находку. Проект на 300 находок — около 2 МБ.

## Что именно ищется

Каждая находка несёт объяснение с последствием, а не только имя правила.

**Токены**

* `token.literal.color` — любой сырой цвет. Подвиды `exact` (точно равен токену), `near` (ΔE < 0.02 — визуально неотличим, и всё равно не токен), `shade`, `foreign`. Ищется в CSS, SCSS, styled-components, emotion, инлайновых стилях, презентационных атрибутах SVG и в обычных строках TypeScript.
* `token.literal.dimension` — сырой размер. `onScale` / `offScale` / `noScale`. Для отступов, у которых в ките шкалы нет, вердикт опирается на частоту значений в самом проекте.
* `token.typography.partial` — кегль из токена, интерлиньяж руками. Самое частое реальное отклонение.
* `token.tier.violation` — `ref`-переменная там, где есть `sys`-роль. Единственное правило, которое срабатывает на коде, делающем всё правильно: `var(--sds-eng-palette-electric-electric700)` — это краска, а не роль, и она не переключится в тёмной теме.
* `font.foreign` — гарнитура вне стека кита.

**API кита**

* `prop.invalid` — `view="danger"` при `{primary, secondary, negative}`.
* `api.deprecated`, `api.dnu` — устаревший символ, импорт из `_DNU_ST_`.
* `import.bypass` — прямой импорт `@v-uik/*` мимо обёртки кита.
* `import.internal` — `@sds-eng/base/src/…` в обход публичной бочки.

**Переопределения** (`style.override.*`) — политика по CSS-свойствам: раскладка не находка, перекраска — warning, приватный `@inner`-слот и `!important` — error.

**Иконки** — эталон извлекается из 466 SVG кита (233 иконки × 2 размера) в `artifacts/kit-icons.json`; сравнение — по точному геометрическому фингерпринту рисунка (нормализованные path-данные), устойчивому к шуму экспорта: порядку атрибутов, точности чисел, метаданным.

* `icon.inline-svg` — `<svg>`, вставленный в код. Совпадение с китом → warning с именем иконки; без пары → `candidate` в набор.
* `icon.foreign-file` — импортированный `.svg` или `url(*.svg)` в стилях, те же два вердикта.
* `icon.foreign-pack` — сторонние наборы (react-icons, @mui/icons-material, lucide-react и т.п.).

«Похожа, но перерисована» статически недоказуемо — такого вердикта нет; это уровень ИИ-этапа (M5). В дашборде — галерея «Иконки мимо кита» с отрисовкой совпавших иконок.

**Доступность** (`a11y.*`) — фокус, клавиатура паттернов, ARIA-связи и атрибуты, доступные имена, контраст — на базе `kit-a11y.json`.

**Ещё не сделано:** скоринг кастомных компонентов (`component.custom` / `.novel` / `.fork`) — эвристика по имени уже в отчёте, полноценный скоринг в M5.

## Что сканер переваривает

SCSS- и CSS-модули, глобальные таблицы стилей, styled-components, emotion, инлайновые `style={{…}}`, JSS, дизайн-литералы в обычном TypeScript.

Никаких допущений о структуре проекта: `src/` не обязателен, фреймворк любой, монорепа поддерживается. Алиасы читаются из пяти источников (`tsconfig`, `vite`, `webpack`, `craco`, `next`, `package.json#imports`), и конфиги **разбираются статически, а не выполняются**.

Кит находится по факту, а не по имени: если у вас есть своя ре-экспортная бочка

```ts
// src/shared/ui/index.ts
export { Button, Modal } from '@sds-eng/base'
```

то `import { Button } from '@/shared/ui'` всё равно опознаётся как использование кита. Наивный сканер здесь решил бы, что кит не используется, и нарисовал бы идеальный балл.

Значения находятся и там, где их обычно не ищут: внутри тел функций, в хелперах, собирающих объект стиля, в возвращаемых значениях и в аргументах вызовов.

Проверено на: `demo-app`, всём `ui-kit-eds-ce` (2378 файлов, yarn workspaces), самом `ds-analyzer` (честно отвечает «кит не используется»), Next.js app-router без `src/`, без `tsconfig`, на `.jsx`, с переименованным китом.

## Настройка под проект (необязательно)

Всё работает без конфига. `ds.config.json` в корне проекта нужен только для того, до чего статический разбор не дотягивается:

```jsonc
{
  "kitPackages": ["@company/design-system"],
  "exclude": ["**/*.generated.tsx"],
  "aliases": { "@ui/*": ["src/shared/ui/*"] },
  "rules": { "token.literal.dimension": "off" },
  "ignoreFindings": ["f_0041"],
  "ci": {
    // переопределение для нестандартных случаев; обычно НЕ нужно —
    // репозиторий и целевая ветка определяются из git-чекаута проекта сами
    "repositoryUrl": "https://…/project.git",
    "targetBranch": "master"
  }
}
```

## Из отчёта — сразу в pull request

У авто-фиксимых решений в «Плане работ» (и у отдельных вхождений в «По файлам» / «Подряд») есть чекбоксы. Выбор поднимает нижнюю панель: сколько решений, правок и файлов уйдёт в PR. Кнопка **«Создать PR»** открывает форму и отправляет в Jenkins generic-webhook-trigger тело `{repository_url, branch_name, target_branch, pr_title, pr_body, diff_content}`.

Ничего настраивать не нужно: вебхук конвейера зашит константой, **репозиторий берётся из git-remote анализируемого проекта, целевая ветка — из его HEAD** (читаются при генерации отчёта, без вызова git). Заголовок и описание PR генерируются из выбора и редактируются на месте.

Дифф собирается из тех же `before`/`after`, что показаны на экране, и проходит `git apply`. Пересекающиеся правки и находки без точной замены не выбрасываются молча — они перечислены с причиной. Если браузер блокирует запрос (CORS), рядом кнопка **«Скопировать curl»** — та же команда для терминала.

## Разработка

```bash
npm run verify            # typecheck + lint + 518 тестов
npm run test:coverage
npm run extract           # переизвлечь спеку кита (нужен чекаут ui-kit-eds-ce)
npm run dashboard:build   # пересобрать шаблон дашборда после правок dashboard/src
```

`npm run extract` — единственная команда, которой нужен сам кит. Ищет его так: аргумент → `DS_UI_KIT_ROOT` → `../ui-kit-eds-ce`.

Качество детекторов меряется против размеченного вручную оракула в `demo-app/fixtures/expected-findings.json`: **precision 1.000, recall 1.000** на 98 ожиданиях. Отдельно проверяется, что API-правила дают **ноль** срабатываний на 684 канонических примерах самого кита.

Архитектура целиком — `SPECS/architecture.md`. Контекст для подхвата — `HANDOFF.md`.
