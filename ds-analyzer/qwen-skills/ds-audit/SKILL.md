# ds-audit — аудит проекта на отклонения от дизайн-системы sds-eng

Ты выполняешь строгий сценарий. Не отклоняйся от него. Все команды копируй ДОСЛОВНО,
подставляя только `<PROJECT_DIR>`. Не придумывай свои команды, флаги и пути.

## Правила стабильности (обязательны)

1. Никогда не редактируй код проекта и код анализатора руками.
2. Каждую команду запускай ровно в том виде, как она написана здесь.
3. У каждого шага есть маркер успеха. Нет маркера или код возврата ≠ 0 → покажи
   пользователю последние 20 строк вывода команды и ОСТАНОВИСЬ. Не повторяй команду,
   не пытайся чинить.
4. Читай только те файлы, которые названы в этом сценарии. `findings.json` и
   `usage.json` НЕ открывай — они огромные.
5. Все числа для пользователя бери из JSON-ответа команды `brief`. Ничего не
   пересчитывай и не суммируй сам.
6. `rm -rf` разрешён ровно для одного пути: `$HOME/.cache/ds-analyzer/targets/<имя>`.

## Фаза 0 — проверка среды

Выполни по очереди:

```bash
node --version
```

Маркер успеха: версия v20 или новее. Иначе скажи пользователю установить Node.js ≥ 20 и остановись.

```bash
git --version
```

Маркер успеха: любая версия. Иначе скажи установить git и остановись.

```bash
test -f "$HOME/.qwen/skills/ds-audit/scripts/ds.mjs" && echo SKILL_OK
```

Маркер успеха: `SKILL_OK`. Иначе скажи: «Скилл установлен неполно — запустите
install-skills.sh из дистрибутива ds-analyzer» и остановись.

## Фаза 1 — какой проект анализируем

- Если пользователь уже сказал «текущий проект» / «этот проект» — возьми текущий каталог:
  `PROJECT_DIR` = результат команды `pwd`.
- Если пользователь уже дал git-URL — иди в ветку «удалённый репозиторий».
- Если непонятно — задай вопрос инструментом `ask_user_question`:
  - Вопрос: «Какой проект анализируем?»
  - Вариант 1: «Текущий каталог» (подставь в описание вывод `pwd`)
  - Вариант 2: «Удалённый репозиторий — вставьте git-URL» (вариант со своим ответом)

### Ветка «удалённый репозиторий»

`<ИМЯ>` — последний сегмент URL без `.git` (пример: `git@host:team/shop-app.git` → `shop-app`).

```bash
rm -rf "$HOME/.cache/ds-analyzer/targets/<ИМЯ>" && git clone --depth 1 <URL> "$HOME/.cache/ds-analyzer/targets/<ИМЯ>"
```

Маркер успеха: код возврата 0. При ошибке покажи stderr, переспроси URL один раз
(`ask_user_question`, вариант со своим ответом), после второй ошибки остановись.

`PROJECT_DIR` = `$HOME/.cache/ds-analyzer/targets/<ИМЯ>`.

### Ветка «текущий каталог»

```bash
ls package.json src 2>/dev/null | head -3
```

Если вывод пуст — предупреди: «Каталог не похож на JS-проект», и спроси через
`ask_user_question`: «Всё равно анализировать?» (Да / Нет). «Нет» → остановись.

## Фаза 2 — запуск анализа

Выполни три команды строго по очереди. `<PROJECT_DIR>` подставляй как абсолютный путь.

```bash
node "$HOME/.qwen/skills/ds-audit/scripts/ds.mjs" analyze "<PROJECT_DIR>"
```

Маркер успеха: в конце вывода строка с «dashboard.html ← откройте двойным кликом».
Команда может работать до нескольких минут — жди.

```bash
node "$HOME/.qwen/skills/ds-audit/scripts/ds.mjs" patches "<PROJECT_DIR>"
```

Маркер успеха: JSON в stdout с полем `totals`.

```bash
node "$HOME/.qwen/skills/ds-audit/scripts/ds.mjs" brief "<PROJECT_DIR>"
```

Маркер успеха: JSON в stdout с полем `"$schema": "ds-analyzer/brief@1"`.
Этот JSON — единственный источник чисел для следующей фазы.

## Фаза 3 — отчёт пользователю

Составь отчёт ПО-РУССКИ строго из полей brief-JSON, по этому шаблону:

- Здоровье проекта: `health.score`/100
- Отклонений: `totals.findings` (ошибок `totals.errors`, предупреждений `totals.warnings`),
  уникальных решений: `totals.decisions`, доступность: `totals.a11y`
- Состав интерфейса: из ДС `shares.kit`% · кастомные на токенах `shares.customTokens`% ·
  кастомные без токенов `shares.customHardcode`% (проценты уже замкнуты на 100)
- Покрытие токенами: `tokenCoveragePercent`%
- Топ проблем: первые 5 из `topProblems` — «правило: actual → expected (occurrences×)»
- Готово к автофиксу: `recommendedFixes.decisions` решений в `recommendedFixes.files` файлах
- Дашборд: file://-ссылка на `artifacts.dashboard`
- Артефакты: `artifacts.findings`, `artifacts.usage`, `artifacts.summary`, `artifacts.patches`

## Фаза 4 — что дальше

Задай вопрос инструментом `ask_user_question` (один вариант):

- Вопрос: «Что дальше?»
- «ИИ-разбор топ-5 кастомных компонентов» → выполни скилл **ds-deep** (передай PROJECT_DIR)
- «ИИ-разбор всех кастомных компонентов» → выполни скилл **ds-deep** с пометкой «все»
- «Применить рекомендованные автофиксы (ветка + коммит + пуш)» → выполни скилл **ds-fix**
- «Закончить» → повтори пути к дашборду и артефактам, останься в ожидании.
