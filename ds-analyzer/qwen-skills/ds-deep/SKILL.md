# ds-deep — ИИ-разбор кастомных компонентов

Требуется завершённый аудит: в `<PROJECT_DIR>/ui-analyzer/` уже лежат артефакты.
Если их нет — сначала выполни скилл **ds-audit**.

Правила стабильности те же, что в ds-audit: команды дословно, при ошибке — показать
вывод и остановиться, файлы проекта руками не менять.

## Шаг 1 — собрать пакеты контекста

По умолчанию топ-5; если пользователь просил «все» — используй `--all` вместо `--top 5`.

```bash
node "$HOME/.qwen/skills/ds-audit/scripts/ds.mjs" deep-pack "<PROJECT_DIR>" --top 5
```

Маркер успеха: JSON в stdout с полем `packs` — список
`{component, file, usages, packFile, bestCandidate}`.

## Шаг 2 — вынести вердикты, по одному

Для КАЖДОГО элемента `packs`, строго по одному (не читай несколько пакетов сразу):

1. Прочитай файл `packFile`. В нём есть всё: исходник компонента, кандидаты из кита с
   карточками, каталог кита T0 и шаблон ответа. Ничего другого не открывай.
2. Заполни шаблон ответа из конца пакета — дословно его форму, ничего не добавляя.
   Правило уверенности: `high` только если минимум 2 из 3 линз (API, поведение, стили)
   получили «да». Не выдумывай пропы, которых нет в карточках.
3. Дозапиши заполненный шаблон в файл `<PROJECT_DIR>/ui-analyzer/deep/verdicts.md`
   (создай файл при первом вердикте; каждый вердикт отделяй строкой `---`).

## Шаг 3 — сводка пользователю

Покажи таблицу по-русски: Компонент · Вердикт · Уверенность · Первый шаг плана.
Под таблицей: «Полные вердикты: `<PROJECT_DIR>/ui-analyzer/deep/verdicts.md`».

Затем задай вопрос `ask_user_question` (один вариант):

- Вопрос: «Что дальше?»
- «Применить рекомендованные автофиксы (ветка + коммит + пуш)» → выполни скилл **ds-fix**
- «Разобрать остальные кастомные компоненты» → повтори этот скилл с `--all`
- «Закончить» → останься в ожидании.
