## 0. Как запустить прямо сейчас

```bash
cd ds-analyzer
npm install
npm run analyze -- /path/to/your-project
```

Пишет в `<project>/ui-analyzer/`: `dashboard.html` (открыть двойным кликом), `findings.json`, `usage.json`, `summary.json`, `project-profile.json`, `.cache/observations.json`.

| Флаг | Зачем |
|---|---|
| `--kit-package @company/ds` | кит опубликован под своим именем |
| `--exclude 'src/legacy/**'` | добавить исключения (синтаксис .gitignore) |
| `--out <dir>` | писать не в проект |
| `--artifacts <dir>` | другая версия спеки кита |
| `--no-dashboard` | только JSON |

`npm run verify` — typecheck + lint + 785 тестов. `npm run extract` — переизвлечь всю спеку кита (нужен чекаут `ui-kit-eds-ce` рядом): tokens, components, icons, knowledge (+ отдельно `extract:kit-a11y` с probe-install апстрима). `npm run build:skills` — собрать дистрибутив Qwen-скиллов со встроенным дымовым тестом.

**Что прогонялось:** `demo-app`, весь `ui-kit-eds-ce` (2378 файлов), сам `ds-analyzer`, Next.js app-router фикстура, изолированная копия без кита и node_modules.

## 1. Что это за проект

Двухчастная система вокруг дизайн-системы `sds-eng`:

1. **Извлечение спеки кита** → машиночитаемые JSON-артефакты в `ds-analyzer/artifacts/`. **Готово** (см. §3).
2. **Анализ продуктовых проектов** на отклонения, с дашбордом, PR-конвейером и (M6) ИИ-подсказками.

Конечная цель: разработчик в Claude Code пишет `/ds-audit`, получает отчёт со всеми отклонениями, диффами и предложениями замен; выбранные автофиксы уходят в Jenkins → pull request.

## 5. Дашборд (`ds-analyzer/dashboard/`, dist закоммичен)

4 экрана, всё по-русски. Единица — **решение** (группировка по `impactKey`).

- **Сводка**: компактное здоровье + сетка 4×2 (Отклонения · Решений · Авто-фикс · Компоненты из ДС с «из них без нарушений» · Кастомные на токенах ДС · Кастомные без токенов ДС · Покрытие токенами · Доступность). Все доли компонентов — от одного знаменателя (`usage.elementBreakdown`, замыкается на 100%).
- **План работ**: решения по эффекту, фасетные фильтры, режим «Подряд», чекбоксы на автофиксах.
- **По файлам**: мастер-детейл, правки в порядке строк.
- **Дизайн-система**: кандидаты в ДС, кастомы с кодом + скоринг-кандидаты + токен-вердикты с фильтрами, галерея иконок (отрисовка из геометрии), палитра, шкалы, топ токенов, матрица компонентов.

**PR-конвейер**: выбор автофиксов → unified diff в браузере (проверен `git apply`, пересечения не выбрасываются молча) → Jenkins generic-webhook-trigger. Вебхук зашит константой в `PrFlow.tsx`; `repository_url` и `target_branch` определяются из git-чекаута анализируемого проекта; curl-фолбэк при CORS.

Навигация в URL; переход = сброс фильтров. Контракт `dashboard/src/contract.ts` сверяется с zod-схемами типовым тестом.

## 7. M6 — агентная обёртка (реализована под Qwen Code)

Целевой хост — **Qwen Code**: скилл = папка с инструкциями и скриптами в `~/.qwen/skills/`. Ставка на «глупую» модель-исполнителя: каждая команда дословная, с маркером успеха и одной веткой ошибки; модель никогда не собирает контекст и не считает числа сама.

- **Исходники**: `ds-analyzer/qwen-skills/{ds-audit,ds-deep,ds-fix}/SKILL.md` (по-русски) + `install-skills.sh`.
- **Сборка**: `npm run build:skills` → `dist/qwen-skills/` (в git не коммитится). `ds-audit/scripts/ds.mjs` — один esbuild-бандл (~14 МБ, ESM, чисто-JS движок Shiki — подсветка гарантирована) с подкомандами `analyze | brief | patches | deep-pack | select-patch`; артефакты знаний и шаблон дашборда лежат рядом в `assets/`, скрипт находит их сам через своё расположение. Пользователю нужны **только Node ≥ 20 и git**.
- **Контракты для модели**: `brief` (stdout ≤2 КБ, `ds-analyzer/brief@1`, доли замкнуты на 100), `patches.json` (`ds-analyzer/patches@1`, группы по impactKey с готовыми диффами и `recommendedKeys`), `deep/<Компонент>.md` (пакет ≤8k токенов: исходник + T1-карточки кандидатов + T0-каталог + шаблон вердикта «2 из 3 линз»), `select-patch` → один общий дифф (union, не конкатенация).
- **Дымовой тест встроен в сборку** (провал = провал сборки): копия demo-app во временном git-репо без node_modules → analyze (подсветка обязательна) → patches → brief (сумма долей = 100) → deep-pack → select-patch → реальный `git apply`.
- Поток `/ds-fix` до PR: ветка `ds-fix/<дата>` → `git apply --check` → коммит → пуш → лестница PR: MCP системы контроля версий → `gh pr create` → Jenkins generic-webhook (константы уже в дашборде) → ссылка compare.
- Попутно закрыт баг «фантомной последней строки» (`readSources`): сниппет у конца файла захватывал несуществующую строку, и `git apply` отклонял дифф. Закреплено тестами `src/rules/context.test.ts` и дымовым тестом.

Возможное развитие (не блокирует демо): вариант скиллов для Claude Code, субагент-матчер, генерация кода замены в `/ds-deep`.
